# Безопасность

## Секреты

В репозитории **нет и не должно быть** настоящих ключей. Все секреты передаются только через переменные окружения
(`.env` рядом с `docker-compose.yml`, файл в `.gitignore`):

| Переменная | Назначение |
|---|---|
| `VK_PROTECTED_KEY` | защищённый ключ мини-приложения — проверка подписи параметров запуска |
| `VK_COMMUNITY_TOKEN` | токен сообщества с правом «сообщения» |
| `VK_CALLBACK_SECRET_KEY`, `VK_CALLBACK_CONFIRMATION_CODE` | Callback API группы |
| `DIESEL_MASTER_KEY` | мастер-ключ администратора (≥ 12 символов, пусто — вход выключен) |
| `DIESEL_PIN_PEPPER` | секрет отпечатков ПИН-кодов сотрудников и кодов привилегий (без него API в Production не стартует) |
| `DB_PASSWORD` | пароль PostgreSQL |

Каждый push и pull request проверяется [gitleaks](https://github.com/gitleaks/gitleaks) в CI.

## Что защищено в коде

- Подпись параметров запуска VK (HMAC-SHA256, сравнение за постоянное время); тестовый `X-Test-Vk-Id` принимается только в Development.
- Роли персонала определяются на сервере; ПИН-коды хранятся только как HMAC-отпечатки, 5 ошибок — блокировка на 15 минут.
- Персональные данные: до согласия (152-ФЗ, 18+) сервер не хранит имя и фото гостя; дата и редакция согласия сохраняются.
- Выдача привилегии — только по временному коду с экрана гостя (HMAC, окно 60 секунд, одноразовый); сотрудник (роль Staff) не может начислить и выдать самому себе; администратор может, включая корректировку своего баланса, и это остаётся в журнале аудита.
- Загружаемые фото: тип определяется по содержимому файла (JPEG, PNG, WebP), SVG не принимается, отдача с `X-Content-Type-Options: nosniff`.
- Журнал операций: каждое начисление и списание пишется в той же транзакции, что и изменение баланса; через приложение записи не меняются и не удаляются.
- Денежные операции — атомарные SQL `UPDATE` и `SELECT … FOR UPDATE`; уникальные индексы на чеки, коды купонов и начисления за активность.
- Rate limiting в nginx и API, `statement_timeout` в PostgreSQL, БД и API слушают только `127.0.0.1`.
